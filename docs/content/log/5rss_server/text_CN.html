前天开始折腾RSS，起因是想获取干净、多样、高价值的信息，同时戒掉刷消息的瘾，不再在知乎里“屎里淘金”。另一方面，我在FPGA的时钟数据一致性上栽了大跟头——输入输出总是慢半拍或快半拍，我又不想让AI替我思考，这事儿做得我满心烦躁，根本推进不下去，也不想整个周末都耗在上面，于是转头折腾起了RSS。

今天终于把RSS从服务器到客户端的整套环境都搭建完成了，信息源也搜集得差不多了。其实最后发现，我根本不需要那么多数据源：说实话，金融方面的内容我也看不懂，只是被带节奏罢了; 政治方面，东边有联合早报，西边有加拿大广播电台、us news，其余的大同小异。科技方面，mit review、hacker news能给我提供不少内容。唯一的缺憾是，我没找到合适的随笔类内容。的确, 如今的互联网上，很难找到成规模、结构化输出个人表达的平台了, 有趣的东西往往零星分布在个人博客中, 而这又很难一一整理. 在RSSHub上别人整理的不少读书网站、书屋类的源，现在要么倒闭，要么变成了推销平台，实在是件糟糕的事。所以从整体上看, 过去二十年我们的检索工具和消息接收工具变得越来越强大, 从浏览器到公众号平台到ai, 但是生态却越发封闭——我们看到的一切内容都基于平台而不是自己的选择, 这也正是RSS的目的: 打破这一切, 弱水三千, 取其一瓢: 只要自己真正需要的那一瓢.

不过, 我也不想把RSS深化成打破信息茧房的万能钥匙. 因为事实并不是这样的: 我并不认为信息茧房是现代化信息算法造成的. 只要阅读者有立场, 并且无法事无巨细地获取任何消息的一手资源, 那么信息茧房就是不可避免的——哪怕信息提供商完全中立, 人毕竟愿意在自己感兴趣的舒适圈浏览. 就像互联网出现之前, 各种报纸的受众就大不相同, 人的天性就是不愿意看到有人反对自己. 而RSS毕竟不能改变这一切, 你的信息源都是自己选的, 它只能看起来更干净, 但绝非不可能保证公正客观.

下面是配置的具体流程, 因为全程都是和agent慢慢对话搭起来的, 索性就由它总结一下了:

  • 什么是RSS?

    • 即“简易信息聚合协议”, “聚合”的意思就是说: 之前刷B站、翻知乎、蹲博客要打开不同的app或网站，现在通过RSS server把不同信息源爬一遍, 做一个收集, 把所有你想看的内容都薅到一个地方，像喂饭一样送到你眼前(RSS阅读器).

  • 为什么要自建RSS server?

    • 其实也可以不用, 可以去RSSHub的网站上查找当前开放的公共服务器. 但是, 公共服务器是别人为爱发电运行, 并不稳定, 今天有点爱, 明天可能就没有了; 另一方面, 公共服务器可能不支持你想要的某个源, 个人服务器完全可以自己折腾. 最后一点, 国内的公共服务器理论上爬不到国外的源, 而把海外服务器作为个人RSS服务节点, 反而能省下自己的VPN流量.

  • 如何配置RSS server?

    • RSSHub（官方仓库：https://github.com/DIYgod/RSSHub）, 名声大, 社区大, 对低配服务器也友好(512MB内存+20GB硬盘就能跑).
    • 就是2026年这大环境得说清楚：B站、微博这些主流平台因为反爬，大部分源会报503，但新闻网站, 小众博客、政府公告、GitHub这些源还是稳得一批，自定义源是随便玩。
    • 配置过程(傻瓜式容器一键启动)
    • 安装Docker Engine：仅安装Docker Engine，不安装Docker Desktop(后者适用于Windows/Mac，Linux服务器安装会浪费内存)。
    • curl -fsSL https://get.docker.com | bash
    • 清理同名旧容器（避免冲突报错）:
    • docker stop rsshub && docker rm rsshub
    • 一键启动RSSHub（针对512MB内存调优参数，直接复制粘贴执行）：
       docker run -d \
   --name rsshub \
   --restart always \
   -p 4096:1200 \
   -e NODE_OPTIONS="--max-old-space-size=200" \
   -e CACHE_TYPE=memory \
   -e CACHE_EXPIRE=300 \
   -e ACCESS_CONTROL_ALLOW_ORIGIN=false \
   --memory=400M \
   --memory-swap=400M \
   --cpus=0.5 \
   --log-opt max-size=10m \
   --log-opt max-file=3 \
   diygod/rsshub:alpine
    • 浏览器访问 http://你的服务器IP:4096

  • 如何配置RSS阅读器?

    • 最影响体验的一部分, 我的评价是:
    • Fluent Reader: 非常简洁, 功能流畅, 但是没有ai翻译, 自己读BBC, CNN, 看两篇就分不清26个字母了
    • Folo: 商业化太重, 自定义api还收费, 到处都是ai聊天的窗口. 额, 作者想赚我钱还是歇歇吧, 吃相太难看.
    • MrRSS(https://github.com/WCY-dt/MrRSS): 最终选择, 非常不错.
      • 轻量化：资源占用极低，低配手机/电脑运行流畅，无广告。
      • AI兼容性：支持订阅内容摘要生成、AI翻译等功能，完全自定义api, 远超上述两款。
      • 作者维护积极：GitHub仓库issue回复及时，更新频率高。
      • 开箱即用：安装后填入RSSHub地址即可使用，macOS/Windows均支持。

总而言之，这台海外的丐版服务器立了大功。如今拥有了自己的RSS服务器，说起来也是一件开心的事。打开MrRSS，就像翻开一份报纸，没有算法推荐，这里的一切都由我自己选择。

说来搞笑，因为很多RSS链接都返回503错误，我还以为RSSHub的Telegram群组会有新的解决方案，于是中午花了很久注册Telegram账号——这本是2023年高考暑假就想做的事，只是当时手机号收验证码太麻烦，最终只留下了Telegram和Instagram这两个漏网之鱼。好不容易完成注册，为此甚至在PayPal上传了身份证和银行流水（privacy -10000），加入群组后却发现大家都在闲聊扯皮、发广告，上一条有价值的RSS分享还是两年前的事, 晕死……在网站反爬虫机制和小众优质站点倒闭的双重夹击下，RSS社区已经濒临消亡，说什么大语言模型可以通过聚合RSS源来获取训练数据，纯粹是天方夜谭。

但对我个人而言，打开电脑，无需开启加速器，只需点击更新按钮，就能看到东西方不同的观点、最新的新闻和有趣的早报，我已经很知足了。
